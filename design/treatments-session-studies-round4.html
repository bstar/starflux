Splitting is an action.

One shared feature across all eight treatments, independent of the visual style.

01 / START

One active terminal

Tabs and the session index select the terminal shown in the active pane. They don’t automatically divide the screen.

02 / SPLIT

Choose a direction

Split right or below. A new shell opens in that pane; an existing session stays available in its tab.

03 / ARRANGE

Resize and focus

Drag the divider, or focus it and use arrow keys. Split a pane again to try a nested arrangement. ↗ focuses one pane temporarily.

04 / RETURN

Keep the sessions

Close a pane with ×, or keep only the focused pane. Its session remains in the tab strip for later.

These are interactive feature studies. The installed application still needs the selected treatment and splitting behavior implemented.

The app belongs in the workspace.

A STAR/SCREEN-style private desktop, presented as an ordinary session panel.

01 / LAUNCH

Local or over SSH

Choose the app command and its working directory on that host. Open a tab, or explicitly split the focused pane.

02 / PRESENT

A virtual app surface

The app runs in a private compositor on its host. Its pixels appear in the panel. Existing terminal sessions stay available.

03 / CONTROL

Capture and release

Give keyboard and pointer input to the app. Ctrl+Esc releases input. Switching sessions releases capture too.

04 / RECONNECT

Keep the remote app

Reconnect to the existing app session after a transport interruption. Desktop drops must stage files on that app’s host before delivery.
