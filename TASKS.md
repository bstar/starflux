# STAR MUX implementation tasks

Task checkboxes reflect completed acceptance criteria; the demo progress below also records partial work. Complete each task's acceptance condition before marking it done. The [plan](docs/plan.md) defines architecture, scope and release gates. Task dependencies describe execution order, not a request for parallel agents.

## M0 Integration proof

- [x] **T01 Record the development baseline.** Inspect applicable repository instructions and source licenses; record Rust, STAR/KIT, STAR/SCREEN, Kitty, Wayland, SSH and installed Codex versions. Identify an available remote test host and authentication without storing secrets. Deliver a compatibility and dependency inventory. **Accept:** builds are reproducible through official packages or Nix, source revisions are pinned, and missing external prerequisites are explicit. **Depends:** none.
- [x] **T02 Build the experiment skeleton.** Add the Rust project, STAR/KIT scene, experiment switches and a synthetic harness. Keep source overrides explicit and production pins immutable. Deliver launch and cleanup commands. **Accept:** a fresh checkout can build the skeleton; launch and exit restore terminal state and leave no unintended processes. **Depends:** T01.
- [ ] **T03 Prove persistent terminal ownership.** Build minimal local and remote session workers, a terminal attach client, host handshake and reconnect. Deliver a shell that is observed through Kitty without Kitty owning its lifetime. **Accept:** closing the frontend and breaking SSH preserve the same remote PID and session ID; resize and Ctrl+C work; stop terminates only the selected session. **Depends:** T02.
- [ ] **T04 Embed two actual Kitty surfaces.** Adapt the smallest viable STAR/SCREEN compositor path into the experiment and connect it to STAR/KIT. Deliver independent local and remote terminal panes. **Accept:** focus, Unicode, selection, clipboard, key release, resize and Ctrl+Esc work without cross-pane input; window gestures and file drops are tested separately. **Depends:** T03.
- [ ] **T05 Capture and transfer one real desktop drop.** Route a PNG from a file manager to the selected remote session using private staging and atomic completion. Deliver progress, cancellation and destination identity. **Accept:** remote bytes and digest match; a focus change cannot redirect the upload; interrupted transfer never exposes a ready partial file; the original remains intact. **Depends:** T04.
- [x] **T06 Attach the uploaded screenshot to existing remote Codex.** Establish the installed harness's supported attachment behavior and create the first adapter. Deliver an editable prompt with an actual image attachment. **Accept:** an already-running remote Codex session answers a question about the dropped image after the user submits; no manual scp, local-path substitution, process restart or automatic prompt submission is required. Record version and evidence. **Depends:** T05.
- [ ] **T07 Compare presentation and restoration approaches.** Measure the inside-Kitty path and a minimal standalone window; test retained Kitty and reconstruction after surface loss. Exercise terminal graphics over the relay, including remote path/shared-memory references. **Accept:** record input/display latency, image quality, scaling, CPU, GPU, memory, drop routing and restoration limits with reproducible commands; no false claim of full graphics replay. **Depends:** T04; final comparison includes T06.
- [ ] **T08 Record architecture decisions.** Choose presentation, compositor reuse boundary, session supervision, reconstruction strategy and harness attachment path. Deliver decision records with alternatives, evidence and consequences. **Accept:** the M0 demonstration passes with two Kitty panes, remote image attachment, frontend loss and SSH reconnect, or a concrete failing gate and revised design are recorded before feature expansion. **Depends:** T06, T07.

## M1 Runtime foundation

- [ ] **T09 Implement the domain model.** Define stable hosts, projects, worktrees, tasks, runs, sessions, panes, attachments and transfers. **Accept:** replacing a pane preserves task and session identity; process, host connection and agent state are independent. **Depends:** T08.
- [ ] **T10 Stabilize the protocol.** Add version negotiation, bounded framing, errors, request IDs, cancellation, event cursors and idempotency. **Accept:** malformed or oversized messages fail safely; duplicate retries do not duplicate sessions or attachment delivery; slow subscribers resnapshot. **Depends:** T09.
- [ ] **T11 Productize session supervision.** Apply the chosen worker and terminal-state strategy, input leases, process groups, backpressure and scoped stop behavior. **Accept:** the persistence table in the plan is tested; stale clients cannot inject input or resize; Kitty/compositor crashes do not kill agent PTYs. **Depends:** T10.
- [ ] **T12 Implement OpenSSH host management.** Support configured aliases and jump hosts, host capabilities, reconnect and authentication errors. **Accept:** two hosts fail and reconnect independently; remote agents survive transport loss; protocol skew produces an actionable message; helpers launch once. **Depends:** T10, T11.
- [ ] **T13 Add durable storage and recovery.** Add SQLite schema migrations, atomic session metadata, quotas and native session references. **Accept:** interrupted writes recover; restart does not duplicate runs or replay tool actions; reboot recovery accurately reports stopped processes. **Depends:** T09, T11.
- [ ] **T14 Ship runtime CLI and diagnostics.** Implement launch, list, attach, detach, inspect and scoped stop. **Accept:** scripts can identify sessions by stable ID; reports distinguish agent, transport and presentation failures and redact sensitive content. **Depends:** T12, T13.

## M2 Daily agent workspace

- [ ] **T15 Build project and pane navigation.** Add STAR/KIT project list, tabs, splits, pane zoom and persisted layout. **Accept:** keyboard and pointer navigation work at small and large viewports; hidden agents remain alive; active and read-only attachments are distinct. **Depends:** T14.
- [ ] **T16 Productize the Codex adapter.** Normalize supported lifecycle and native session events, attachment capabilities and resume behavior. **Accept:** capability detection is versioned; unsupported events remain unknown rather than guessed; synthetic tests and a real Codex session agree on tested transitions. **Depends:** T14, T06.
- [ ] **T17 Add the attention queue.** Show questions, approvals, failures and completions with source and age. **Accept:** stale or duplicate events do not create false work; reconnecting is not shown as agent failure; choosing an item focuses the correct run. **Depends:** T15, T16.
- [ ] **T18 Add tasks and worktrees.** Support task ownership, dependency links, explicit worktree creation and review context. **Accept:** dirty work is preserved; task completion is separate from idle/process exit; reopening a task locates its runs and artifacts. **Depends:** T13, T15, T16.
- [ ] **T19 Validate adapter independence.** Add a second user-selected harness through the existing adapter interface and keep a shell fallback. **Accept:** generic terminals work without an adapter; structured and heuristic states are visibly distinguishable; adding the harness does not require rewriting pane or transfer routing. **Depends:** T16, T17.

## M3 Files and graphical review

- [ ] **T20 Complete the transfer lifecycle.** Add manifests, quotas, checksums, collision handling, retry or resume, delivery deduplication and attachment retention. **Accept:** reconnect does not duplicate attachments; committed files survive pane closure while referenced; disk-full and permission failures are actionable; sandbox-readable staging is validated. **Depends:** T12, T13, T16.
- [ ] **T21 Add desktop sources and file types.** Support multiple files, directories, explicit symlink policy, clipboard images, temporary screenshot offers and a file picker. **Accept:** real desktop tests cover spaces, Unicode, identical names, disappearing offers and local/remote destinations; canceled operations preserve originals. **Depends:** T20.
- [ ] **T22 Complete remote drop routing.** Cover pane changes, overlays, two different hosts, generation changes and host disconnection during transfer. **Accept:** an upload remains bound to its selected destination; closing or replacing a pane cannot deliver it to a different agent; transfer readiness and harness acceptance remain distinct. **Depends:** T17, T20, T21.
- [ ] **T23 Add graphical task and artifact review.** Build task dependencies, diff review, artifact previews and explicit remote artifact export using STAR/KIT. **Accept:** preview workers do not block terminal input; references resolve on the owning host; large files are bounded; adopting changes preserves unrelated work. **Depends:** T18, T20.
- [ ] **T24 Meet graphics and input budgets.** Add damage tracking, hidden-pane throttling, bounded frame coalescing and measured presenter improvements. Prototype a GPU scene backend only if results justify it. **Accept:** publish baseline and changed results at 1080p/4K and two/eight panes; meet or explicitly revise the plan's provisional budgets; ordered terminal bytes remain intact under graphics and transfer load. **Depends:** T07, T15, T23.

## M4 Hardening and release

- [ ] **T25 Run fault and soak tests.** Exercise frontend/compositor/Kitty death, SSH loss, worker/daemon restart, replay limits, large output and concurrent transfers. **Accept:** a two-hour eight-agent soak has bounded queues and memory, correct session identities, no duplicate workers and documented recovery behavior. **Depends:** T11, T12, T22, T24.
- [ ] **T26 Package reproducible builds.** Pin dependencies, remove mandatory sibling checkouts, publish build instructions, schema compatibility, source notices and optional feature requirements. **Accept:** a clean Linux environment installs and launches using official packages or Nix; missing graphics/remote capabilities produce useful diagnostics. **Depends:** T24, T25.
- [ ] **T27 Complete desktop acceptance and release notes.** Run the full drop matrix, IME, selection, clipboard, key phases, scaling, resize and reattachment using real Kitty/Wayland. **Accept:** evidence identifies exact versions and hardware; existing remote Codex image delivery passes; documented limitations match observed behavior. **Depends:** T19, T21, T22, T25, T26.
- [ ] **T28 Implement the preferred App shelf layout, project spaces, terminal tabs and explicit splits.** Within the active project, provide Agent, Terminals and Apps spaces. Keep shells in terminal tabs; support explicit split right/below, nested splits, pointer/keyboard resizing, focus/restore and pane closure without stopping the session. Provide an optional agent companion alongside the app desktop. **Accept:** selecting a terminal does not create a split; project/space changes retain agents and terminal PIDs; input, resize and local/SSH drops target the chosen session; saved splits are restored explicitly. The live App Shelf baseline implements these spaces, terminal tabs, an explicit resizable side-by-side split and session retention. Nested/below splits, temporary pane zoom and richer pane closure remain pending. **Depends:** T03, T04, T30.
- [ ] **T29 Add project virtual desktops for local and SSH apps.** Launch the project app from its saved command, then add supporting apps as windows within its virtual app space. Use STAR/SCREEN’s private-compositor model on each app host. Preserve per-window host ownership when mixing local and SSH app surfaces. Launch with structured arguments and host-owned directories, negotiating remote helper/graphics capabilities. **Accept:** multiple real app windows can be focused, moved, tiled, minimized and restored; a real remote GUI app streams into the desktop; keyboard/pointer capture and Ctrl+Esc release work; switching projects/spaces releases input; reconnect retains processes; resize, clipboard and file staging target the app’s host. Launch failures remain visible without disrupting the agent or shells. The live app now launches, focuses, tiles and maximizes real local/SSH app windows, with persistent compositor ownership, bounded frame transport and explicit input release. GPU loopback SSH acceptance passed, including native app keyboard input and worker/window identity across workspace close/reopen. Arbitrary GUI native drag-and-drop, outward clipboard export and the full resize/latency matrix remain pending; current GUI file delivery uses a host-staged URI clipboard offer. **Depends:** T03, T04, T11, T30.
- [x] **T30 Make the project the persistent workspace container.** Store a stable project identity, local/SSH host, directory, agent command and conversation/session, terminal tabs, project app command, app windows, selected space and arrangements. Provide project creation, switching and agent start/attach. Migrate existing workspaces without restarting user agents or discarding terminals. **Accept:** two projects, one local and one SSH, keep separate agent/terminal/app state; switching and reconnect preserve process identity; project launch commands inherit the correct host/directory; supporting apps may select another host with explicit ownership. Implemented in the App Shelf runtime. `scripts/test-app-shelf.py` passed with actual Kitty, local/SSH sessions and GTK apps; process and window identities persisted across project switches, reconnect and workspace close/reopen. Legacy configurations retain their session IDs and assignments. **Depends:** T03, T11.
